How it works

Bytes in, public URL out. Nothing is decoded on the way through.

  1. Agent or curl one request with a bearer token
  2. Prunto sanitizes magic bytes · strip metadata · hash blocklist
  3. Public URL random key, no listing
  4. GitHub PR renders it paste the markdown
  5. Happy review reviewer sees it, approves
  1. Upload. Your agent (or you) posts the file with a bearer token.
  2. Sanitize. Type is checked by magic bytes, metadata is stripped, the hash is checked against the blocklist. No image decoder runs.
  3. Paste. You get a public URL and ready-made markdown for the PR body.
  4. Review. The reviewer sees the change and approves.{{if .HasRetention}} The file is purged after {{.Retention}}, or sooner if you ask.{{else}} The file stays until you delete it, or expires when you ask.{{end}}

The problem

GitHub has no API to attach an image to a PR description. Your agent takes the screenshot and has nowhere to put it.

×Without Prunto

  • You upload every screenshot by hand, for every PR, every time.
  • Agent says "screenshot attached". It is not.
  • You run the branch and drag the screenshot in yourself.
  • Reviewer asks "what does this look like?"
vs

✓With Prunto

  • Agent uploads with one curl, pastes the markdown.
  • Screenshot is in the PR before you open it.
  • Reviewer sees the change in five seconds.
  • Problem No way for an agent to attach an image How A public URL per upload, plus a skill that tells the agent to use it.
  • Problem Screenshots leak or pile up How Your own instance, token-gated, metadata stripped, expiry on your terms.
  • Problem Slow reviews without a picture How Every UI PR ships with proof, every time, because the agent does it.
  • Problem Another paid service How Free, MIT, one container. No bucket, no CDN, no account.

Agent setup

The skill teaches your AI coding agent to upload a screenshot here and paste it straight into a pull request. Install it once for everything you work on, or just for one repository. Either way you need a token — create one in the admin page.

Every project · installs into your home directory 
mkdir -p ~/.claude/skills/prunto-screenshot
curl -sfo ~/.claude/skills/prunto-screenshot/SKILL.md {{.SkillURL}}
export PRUNTO_API_TOKEN=your-token
This repository only · run it in the repo root 
mkdir -p .claude/skills/prunto-screenshot
curl -sfo .claude/skills/prunto-screenshot/SKILL.md {{.SkillURL}}
export PRUNTO_API_TOKEN=your-token

The export lasts until you close the terminal. Put it in your shell profile (~/.zshrc or ~/.bashrc) to keep it.

Or let an AI do it · paste this to any assistant

Configuration

Environment variables. This instance's current values where they are public.

VariableWhat it doesHere
RETENTIONHow long an upload lives. never by default; 30d, 12h, 90m. Each upload can ask for less with expires_in, never more.{{.Retention}}
PRUNTO_BASE_URLPublic origin, used in every URL handed out and in the skill.{{.BaseURL}}
ADMIN_USERGate /admin. Either unset means closed.
ADMIN_PASSWORD
TRUST_PROXYnone, forwarded (your reverse proxy) or cloudflare. Rate limits key on the resulting client address.
DATA_DIRSQLite file and the blobs. One volume, the only thing to back up.
PORTListen port, default 3000.
ANALYTICS_HTMLA tracker <script> tag (Umami, Plausible), rendered on this page only. Its host is allowed by the page's CSP.

Limits

  • PNG, JPEG, GIF, WebP, MP4, WebM. Typed from magic bytes, never from the filename.
  • {{.MaxMB}} MB per file, 50 megapixels per image.
  • Per token: 20 uploads an hour, 200 MB a day.
  • Any upload can set its own expires_in; the instance retention above is the ceiling.
